# 学習記録アプリ 設計案 v0.2（API不要・静的サイト版）

作成日: 2026-11-08 / ステータス: **承認済み** / v0.1（FastAPI＋NAS案）を置き換え。この設計で 2026-11-08 に承認済み

## 方針の変更点
- Claude APIは使わない（費用ゼロを優先）。
- 問題文づくり・リマインドは既存のAI（Claudeのチャットなど）に任せる。アプリは「過去問道場のような出題・回答＋日付つき記録＋ストリーク」に集中する。
- そのため v0.1 の「AIによる抽出・自動対応付け・検索つき解説」は対象外。問題と解答は最初からセットで取り込むので、対応付けの問題自体がなくなる。

## 1. 構成の比較

| | A. GitHub Pages＋端末内保存（推奨） | B. Aに同期を追加（Googleドライブ） | C. NASでサーバーを動かす |
|---|---|---|---|
| 費用 | 0円 | 0円 | 0円（電気代のみ） |
| 準備 | ほぼなし | Google Cloudでの設定が一度必要 | Docker＋Tailscaleの設定が必要 |
| スマホとPCの記録 | 別々。手動でファイルを書き出し／読み込みすれば合わせられる | 自動で同期 | 自動で同期 |
| 外出先 | どこでも使える。オフラインでも動く | 同左 | Tailscale接続が必要 |
| 消えるリスク | ブラウザのデータ削除で消えるため、バックアップが必要 | ドライブに残る | NASに残る |
| 作る量 | 少ない | Aより多い（同期処理の分） | 多い（サーバーとフロントの両方） |

**推奨はA**です。まずAで作って毎日使い始め、PCとの同期が本当に面倒だと感じたら、あとからBを足せます。Aのデータ形式はそのままBでも使えるので、作り直しにはなりません。

**注意点**
- GitHub Pagesは、無料プランでは公開リポジトリで使うのが基本です。公開されるのはアプリのコードだけで、取り込んだ問題や記録はスマホのブラウザ内にしか保存されません。過去問の中身をリポジトリに入れないことをルールにします（著作権への配慮）。コードも非公開にしたい場合は、Cloudflare Pagesなら非公開リポジトリからでも無料で公開できます。
- 端末内に保存する場合、ブラウザがデータを消しにくくなるように「永続ストレージ」を要求します。そのうえでアプリから定期的にバックアップを促します。
- 通知によるリマインドはサーバーなしでは確実に動かないので、既存のAIやカレンダーに任せます（方針どおり）。

## 3. 既存AIで作った問題の取り込み形式

Claudeのチャットなどに「この形式で出力して」と頼むための**指示文テンプレート**を、アプリ内に置いてコピーできるようにします。AIが出したJSONを貼り付ける（またはファイルで渡す）と、検証してから取り込みます。

```json
{
  "format": "study-log/v1",
  "material": { "title": "○○検定 2024年度", "year": 2024 },
  "questions": [
    {
      "ref": "Q1",
      "label": "問1",
      "body": "次のうち正しいものはどれか。$x^2$ ...",
      "type": "choice",
      "choices": [
        { "key": "ア", "text": "..." },
        { "key": "イ", "text": "..." }
      ],
      "answer": "イ",
      "explanation": "要点：...\n\n詳しく：...",
      "tags": ["第3章"],
      "source": "問題集p.12"
    },
    {
      "ref": "Q2",
      "label": "問2",
      "body": "...を求めよ。",
      "type": "numeric",
      "answer": "3.14",
      "tolerance": 0.01
    },
    {
      "ref": "Q3",
      "label": "問3",
      "body": "...を説明せよ。",
      "type": "text",
      "answer": "模範解答 ..."
    }
  ]
}
```

- `type`：`choice`（選択式、自動判定）／`numeric`（数値、許容誤差つきで自動判定）／`text`（記述式。答えを見て自分で○×）
- 取り込み前にプレビューを表示し、形式の誤りは行ごとに知らせる
- **重複検知**：教材名＋問題文＋解答から指紋（ハッシュ）を作り、同じ問題は取り込まない（上書きするか選べる）
- 図が必要な問題用に、画像を添付して手動で登録・編集もできる
- 逆方向として、**回答記録をJSON/CSVで書き出す**機能も付ける。書き出したものをClaudeのチャットに渡せば「苦手な分野の分析」や「似た問題の追加作成」を頼めます

## 4. データモデル（端末内DB）
| テーブル | 主な項目 |
|---|---|
| materials（教材） | id, title, year, created_at, deleted_at |
| questions（問題） | id, material_id, label, body, type, choices, answer, tolerance, explanation, tags, source, fingerprint, created_at, deleted_at |
| images（画像） | id, question_id, role（問題／解答）, blob |
| attempts（回答ログ） | id, question_id, answered_at（UTC）, response, result（正／誤）, judged_by（自動／自己） ※削除しない |
| review_state（復習状態） | question_id, last_result, last_answered_at, wrong_count ※回答ログから作り直せる |
| settings（設定） | timezone=Asia/Tokyo, day_start_hour=4 |

ストリークの計算方法は v0.1 のまま変えません（回答ログから算出、Asia/Tokyoの午前4時で日付を切り替え、今日まだなら「継続中（今日はまだ）」、問題を削除しても記録は残る）。

## 5. 実装計画（新フェーズ1）
1. リポジトリの雛形、CLAUDE.md、docs/、Pagesへの自動公開
2. 端末内DBとストリーク計算＋テスト（3:59／4:00の境界、月またぎ、途切れ）
3. JSON取り込み（検証・プレビュー・重複検知）＋指示文テンプレート
4. 出題画面（1問ずつ → 回答 → 正誤 → 解説、自己判定）と出題順（間違えた問題 → 新しい問題、教材・タグで絞り込み）
5. ホーム（連続日数・今日の状況・「今日の1問」・最長記録・ヒートマップ）
6. 問題一覧・編集・画像添付・論理削除
7. バックアップ（全データの書き出し／読み込み）、回答記録の書き出し
8. PWA化（ホーム画面に追加、オフライン、共有メニューからJSONやテキストを受け取る）
