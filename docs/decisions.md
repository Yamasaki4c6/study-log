# 決定ログ

## 2026-10-29
- 初期設計 v0.1：FastAPI＋React を NAS でセルフホスト、Claude API で抽出・照合・解説（→ 2026-11-08 に撤回）

## 2026-11-08
- 費用面から Claude API は使わない。問題づくり・リマインドは既存 AI（Claude チャット、Meta の Muse）に任せる。
- アプリは「出題・回答＋日付つき記録＋ストリーク」に絞る。問題と解答はセットで取り込むので、自動対応付けは不要になった。
- 構成：GitHub Pages の静的 PWA＋端末内保存（IndexedDB / Dexie）。同期はバックアップの書き出し・読み込み（合体）。Google ドライブ同期は将来の候補。
- GitHub 無料プランの Pages は Public リポジトリが必要なので Public にする。データはコミットしない。
- ルーティングはハッシュ形式（#/quiz）。Pages はサーバー側で URL を振り分けられないため。
- 共有メニュー（Web Share Target）は GET 方式で text を受け取る（サーバー不要）。画像ファイルの共有受け取りは未対応。
- 復習状態は保存せず、回答ログから毎回求める。
- 取り込み形式 study-log/v1 を決定（docs/import-format.md）。
- 問題を作ったら「タップで取り込めるリンク」（#/import?d=圧縮データ）で渡す。データはスマホのブラウザ内にしかなく外から直接書き込めないため、手間を最小にする方法として採用。完全自動（非公開の受信箱リポジトリをアプリが読みに行く）は将来の候補。
- 問題と回答記録を非公開リポジトリ study-log-data で同期する（ユーザーが「GitHub（問題＋記録）」を選択）。詳細は docs/sync.md。
  - 端末ごとに別ファイルへ書き、読むときに合体する（同時書き込みの衝突を避けるため）
  - Claude が追加する問題には固定 id を付ける。教材 ID は教材名から決める
  - 手で編集・削除・貼り付け取り込みした問題は editedAt を付けて edits.json で同期し、問題ファイルの再取り込みより優先する
  - 画像の同期は見送り（バックアップで移す）
